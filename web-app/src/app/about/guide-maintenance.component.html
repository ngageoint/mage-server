How the dynamic user guide works

For developers: no AI required

The guide update process uses deterministic Node scripts, application source and explicitly configured screen captures. Generating, updating, checking, customizing and reading guides requires no AI model, AI API, prompts or AI credentials, and no Replit service. AI may help developers maintain content here in Replit, but the resulting source and scripts work independently in a normal MAGE checkout.

What the guide references

  • docs/user-guides.json holds authored topics, instructions, image placements and source dependencies. Template data-guide identifiers link instructions to current button labels, accessible tooltips and icons.
  • scripts/generate-user-guides.cjs resolves those references, fingerprints tracked sources and produces the guide edition. Missing controls fail generation rather than silently retaining an old label.
  • scripts/guide-scenes.cjs defines navigation steps and expected views; scripts/guide-capture-fixtures.cjs supplies fictional API records. Captures are PNGs, with source and image hashes in docs/guide-captures.json.

What updates automatically—and what does not

Source-linked labels and icons update during generation. Changes to tracked application views invalidate captures; the capture command rebuilds the real Angular app and regenerates registered pictures. The generator does not invent workflow instructions or discover every new screen, dialog, plugin or role. Narrative text and coverage still require a maintainer.

  • Rename a control: keep its stable identifier; regenerate and review the wording. If a control is removed or replaced, update its references.
  • Change a covered view: refresh captures and inspect layout, controls and captions against the new UI.
  • Add a view, dialog or role: add a scenario and fictional fixtures, link the picture to the appropriate instructions, then capture and review.
  • Change a workflow: edit the authored steps and any affected scenarios. Source fingerprints flag review; they cannot infer intended behavior.
  • Edit guide text only: generate and review; unchanged app views need no new capture.

Developer update checklist

From mage-server/web-app (or web-app in a standalone mage-server checkout), install the project's locked dependencies with a supported Node version and build the core library if needed. Install Chrome/Chromium on the build host, put it on PATH or set CHROME_BIN to its executable.

  1. Update the UI, guide instructions, source links and scenarios as needed.
  2. Run npm run guides:capture, then npm run guides:generate.
  3. Inspect changed pictures and read the affected instructions. Correct gaps before acknowledging review; do not use review to suppress a failure.
  4. Run npm run guides:review only after that review, then npm run guides:check and npm run guides:test. The review command acknowledges all current topics.

Normal npm app build hooks check and refresh captures. The development guide watcher regenerates content but does not refresh stale screenshots itself: run the capture command when it reports stale pictures. Missing sources, stale captures and unreviewed changes fail validation. Generated output is not a substitute for reviewing the intended workflow.

Real screens, fictional data and portable packaging

Pictures render the actual compiled MAGE app in an isolated temporary browser profile against fictional API fixtures—not live users, events, observations or a database. Map pictures use MAGE's OpenStreetMap basemap at a fixed documentation area, with attribution. Unregistered API calls fail; external capture requests are restricted to the local fixture server and permitted public font/OSM tile hosts. This is non-AI, not a claim of zero network dependencies.

Current packaged captures let Docker builds and installed MAGE use the guide without a capture browser. Stale pictures must be refreshed on a developer machine before packaging. Pictures represent the compiled source version, not an unrelated older installation. See docs/guide-screen-capture.md for the maintainer procedure.

Administrator edits and offline editions

Administrator overrides are stored separately from generated defaults: section and form-field inclusion, edited text and uploaded pictures with chosen placement survive regeneration. Global changes require the existing settings-update permission; event changes also require access to that event. Event-specific content is subject to event-read authorization. These choices change documentation, not form behavior or application permissions. Manual text and uploaded pictures still need manual maintenance when workflows change.

Offline downloads embed the selected edition and its pictures with the saved customizations. Download again after updates; an existing offline file does not update itself. Administrator editing instructions remain in the separate Admin Guide.
